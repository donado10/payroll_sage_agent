# Orientation

.NET 10 (LTS) worker service, one solution, central package versions. Nullable on, warnings are
errors, and both stay that way.

## Where things live

| Path | What |
| --- | --- |
| `platform/` | the platform's contract, plan and status — GENERATED by igf_payroll, never edited here |
| `src/PayrollSageAgent.Core` | platform-neutral — no Windows API, no SQL: the contract's messages (`Contract/`), the platform client over plain `HttpClient` and the rule for which address to follow (`Platform/`, tested with a stub handler, no server), the binding model, its rules and the `pending\` request format (`Bindings/`), the job runner and the per-binding loop (`Jobs/`), the daily log files (`Logging/`), the service's name and SID (`ServiceIdentity`) |
| `src/PayrollSageAgent.Sage` | reading a Sage 100 database (SQL Server): `SageChartReader` — F_COMPTEG, the check a login must pass before it is bound, and SQL Server's errors in French with their detail |
| `src/PayrollSageAgent.Service` | the ONE executable (`PayrollSageAgent`): the Windows service (`AgentSupervisor`, one loop per binding), its verbs (`Cli/`), the pairing both the verbs and the service run (`Bindings/BindingPairing`), the requests it consumes from `pending\` (`Bindings/PendingRequests`), the binding files (`Bindings/BindingStore`), the secret protectors (`Secrets/`) |
| `installer/windows/` | the texts the deliverables carry, French, for the customer's IT: `LISEZMOI.txt`, `compte-sql-lecture.sql`, `acces-windows.sql`, `exemple-liaison.json`, `exemple-plusieurs-liaisons.json` (in the MSI and the zip), `install.ps1` / `uninstall.ps1` (the zip only) |
| `dist/` | the built MSI, zip and release file, gitignored (`scripts/package.sh`) |
| `tests/` | xUnit v3 test projects, one per `src/` project that has logic |
| `test/sage/` | the SQL Server 2019 container with the restored test company, twice, and a read-only login each — `setup.sh`, `sqlcmd.sh`, `sql/` (`backups/` and `.env` are gitignored) |
| `scripts/` | `dotnet.sh` (the SDK in Docker), `check.sh` (the precheck), `run-service.sh` (the service, in Docker), `package.sh` (the MSI and the zip — `lib/installers.py` in `packaging.Dockerfile`'s container), `sign.sh` (the one signing step), `platform-status.sh` (the SessionStart hook) |
| `docs/project-book/` | the long-form reference |

## [HARD] Dependency direction

```
Service → Sage → Core
Service → Core
Core    → nothing
```

`Core` takes no package that touches Windows or SQL Server, and reaches the platform only through
`HttpClient` — which a test replaces with a stub handler. That is what lets its tests run here, on
Linux, with no server. Something that needs Windows goes in `Service` behind an interface `Core`
declares (`ISecretProtector`); something that needs SQL goes in `Sage` behind `ISageChartReader`.

**This line said « no network » in Core until 2026-10-17**: the platform client belongs with the
contract it speaks, and `HttpClient` is neither Windows nor SQL. Corrected when the client was written.

## One executable

There is one exe for the service AND its verbs, because the installer registers one file and the IT
person of a hosting company types one name. A second project with its own `Main` is a second thing to
install, sign and update.
